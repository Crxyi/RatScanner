      How the scan works

      1. Unpacking. JARs are read exactly like the JVM reads them. Nested JARs (Fabric jar-in-jar, shading) are scanned up to 3 levels deep. Disguised classes, hidden EXE/DLL files, scripts and encrypted blobs are detected.
      2. ASM bytecode. Every instruction of every method is read: calls (Runtime.exec, URLClassLoader, defineClass, Session.getAccessToken, sendChatCommand, setOp …), constants, invokedynamic arguments.
      3. String emulation. A small emulator rebuilds strings that are hidden with Base64, hex, byte arrays or character arithmetic like (char)(47932 - 47815), then checks them again.
      4. Deobfuscation. Obfuscators hide strings behind their own decryption methods (XOR, string tables, keys taken from the stack trace, Base64 …). A sandboxed emulator re-computes those methods – it only knows pure maths and string functions, never files, network or system calls – and writes the clear text back into the code.
      5. What happens when you run it. Every report lists what the file would do on your PC: autostart, services or Java agents, downloads that install more files, changes to other mods, launchers or Discord, backdoors (reverse shells, open ports, Telegram/Discord bot control, tunnels, Tor bridges, UPnP port forwards), firewall/proxy/certificate changes, UAC bypasses, hiding and self-deleting. All of it is worked out from the code – nothing is ever run.
      6. Deep scan – every line. After the quick result, every class is decompiled with Vineflower right in your browser and every single line of the deobfuscated Java source is read again. The report shows how many classes and lines were covered, and you can download the whole deobfuscated source as a ZIP.
      7. In your browser. The scan runs locally in a background worker. The file is never uploaded – only its SHA-256 hash and the verdict are stored so the hash lookup works for everyone.
      8. Programs (.exe, .dll, ELF, Mach-O). PE headers, sections, imports and packers (UPX, Themida, VMProtect, PyInstaller) are analysed, all ASCII and UTF-16 strings are checked, and JARs embedded in programs are unpacked and scanned with all Java engines.
      9. Combinations. Single capabilities are often harmless – the combination is what matters. Over 35 rules link capabilities inside a class and across the whole file.
      10. Verdict. Critical findings → Malicious, strong signs → Suspicious, weak signs → Caution, otherwise Clean.

      Never executed

      Files are only ever read as bytes – inside your browser. Nothing is executed, nothing is loaded as a Java class and the file never leaves your PC, so the scan itself can never infect anyone.

      Limits

      A static scan can never prove a file is safe. Heavily obfuscated code, code that is downloaded later or brand new tricks can slip through. Only run files from sources you trust.
